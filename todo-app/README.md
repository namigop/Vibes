# Todo MVP

Minimal CRUD todo list. Single user, no auth, no categories — just create,
toggle, edit, delete. The whole stack runs with one command.

## Stack

| Layer    | Tech                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| Backend  | Go 1.22, [Chi](https://github.com/go-chi/chi) router, [sqlc](https://github.com/sqlc-dev/sqlc), [pgx/v5](https://github.com/jackc/pgx), [goose](https://github.com/pressly/goose) migrations, [validator/v10](https://github.com/go-playground/validator) |
| Frontend | Next.js 14 (App Router), TypeScript, Tailwind CSS, [@tanstack/react-query](https://tanstack.com/query), [react-hook-form](https://react-hook-form.com) |
| DB       | PostgreSQL 16                                                                              |
| Orchestration | Docker Compose                                                                       |

## Prerequisites

- Docker Desktop (or Docker Engine + Compose v2) running
- Free ports **3000** (frontend), **8080** (backend), **5432** (postgres)
- (Optional) `sqlc` and Go on your host machine — only required to run
  `make generate` from outside the container, or to run the backend outside
  of Docker.

## Quickstart

From the project root (`todo-app/`):

**macOS / Linux / WSL / Git Bash:**

```sh
cp .env.example .env
docker compose build                       # build images
docker compose up -d postgres              # start postgres first
make generate                              # generate sqlc code (one-time)
docker compose up -d                       # start backend + frontend
```

**Windows PowerShell** (no `make` or `cp` by default):

```powershell
Copy-Item .env.example .env
docker compose build
docker compose up -d postgres
docker compose run --rm backend sh -c "go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest && sqlc generate"
docker compose up -d
```

Open <http://localhost:3000> in your browser. The frontend talks directly to
the backend at <http://localhost:8080>.

> The `make generate` step is required because the `internal/store/` package
> is generated by sqlc from `sql/queries.sql` — the backend won't compile
> without it. If you have sqlc installed on your host, you can also run
> `make sqlc` (or `cd backend; sqlc generate` on Windows) instead.

To follow logs:

```sh
docker compose logs -f
```

To stop everything:

```sh
docker compose down
```

The database persists in a named Docker volume (`pgdata`). To wipe it:

```sh
docker compose down -v
```

## API reference

Base URL: `http://localhost:8080/api/v1`

| Method | Path          | Body                                   | Response                              |
| ------ | ------------- | -------------------------------------- | ------------------------------------- |
| GET    | `/todos`      | —                                      | `200 {"items":[Todo]}`                |
| POST   | `/todos`      | `{"title":"...","description":"..."}`  | `201 Todo`                            |
| GET    | `/todos/{id}` | —                                      | `200 Todo` / `404 not_found`          |
| PATCH  | `/todos/{id}` | `{"title"?:"...","description"?:"...","done"?":true}` | `200 Todo` / `400 validation_failed` / `404 not_found` |
| DELETE | `/todos/{id}` | —                                      | `204` / `404 not_found`               |
| GET    | `/healthz`    | —                                      | `200 {"status":"ok"}`                 |

`Todo` shape:

```json
{
  "id": "b7d…",
  "title": "buy milk",
  "description": "2L semi-skimmed",
  "done": false,
  "created_at": "2025-01-01T12:00:00Z",
  "updated_at": "2025-01-01T12:00:00Z"
}
```

Error envelope (used for all non-2xx responses):

```json
{
  "error": {
    "code": "validation_failed",
    "message": "request body is invalid",
    "details": [{ "field": "title", "message": "is required" }]
  }
}
```

### curl examples

```sh
# Create
curl -s -X POST http://localhost:8080/api/v1/todos \
  -H 'Content-Type: application/json' \
  -d '{"title":"buy milk","description":"2L semi-skimmed"}'

# List
curl -s http://localhost:8080/api/v1/todos

# Patch (toggle done)
curl -s -X PATCH http://localhost:8080/api/v1/todos/<id> \
  -H 'Content-Type: application/json' \
  -d '{"done":true}'

# Delete
curl -s -X DELETE -o /dev/null -w '%{http_code}\n' \
  http://localhost:8080/api/v1/todos/<id>
```

## Development workflow

### Hot reload

Both services run with hot reload out of the box:

- **Backend**: source is mounted into the container; [`air-verse/air`](https://github.com/air-verse/air)
  (pinned v1.67.4) watches Go files (excluding `internal/store/`) and rebuilds
  on save. Note air was formerly `cosmtrek/air` — the old import path is
  broken and will fail module validation.
- **Frontend**: source is mounted into the container; Next.js dev server
  hot-reloads React components on save.

If you add a new dependency in `backend/go.mod`, restart the backend
container so the module cache picks it up:

```sh
docker compose restart backend
```

### Migrations

Migrations run automatically when the backend starts. To run them manually:

```sh
# Up
docker compose run --rm backend goose -dir migrations postgres "$DATABASE_URL" up

# Down one step
docker compose run --rm backend goose -dir migrations postgres "$DATABASE_URL" down
```

Add a new migration by creating `migrations/00002_xxx.sql` with the
`-- +goose Up` / `-- +goose Down` annotations, then mirror the final schema in
`sql/schema.sql` so sqlc can introspect it.

### sqlc

The `internal/store/` package is **generated** by sqlc — never edit those
files by hand. The `sql/queries.sql` file is the source of truth; the
generator emits typed Go methods from it.

To regenerate after editing `sql/queries.sql` or `sql/schema.sql`:

```sh
make generate         # installs sqlc inside the backend container and runs it
# or, if you have sqlc locally:
make sqlc
```

Install sqlc on your host (optional): <https://docs.sqlc.dev/en/latest/overview/install.html>

### Integration tests

The backend has integration tests that boot a real Postgres container via
testcontainers. They live in `backend/tests/integration_test.go`.

```sh
make generate       # generate internal/store first
make test           # run inside the backend container
```

Expected coverage:

- Happy path: create → list → get → patch → delete → list (empty)
- Validation: empty title → `400 validation_failed`
- Not found: unknown id → `404 not_found`

## Troubleshooting

### Port already in use

If 3000, 8080, or 5432 is taken, edit `.env` and restart:

```sh
BACKEND_PORT=8081
POSTGRES_PORT=5433
docker compose down && docker compose up -d --build
```

### Backend fails to start with "connection refused" to postgres

`depends_on: { condition: service_healthy }` should prevent this. If it
happens anyway, check that the postgres container is healthy:

```sh
docker compose ps
docker compose logs postgres
```

### `internal/store/` missing

You haven't run sqlc yet. Either run `make generate` (no host tools needed)
or `make sqlc` if you have sqlc installed locally.

### CORS error in the browser

The backend's `CORS_ALLOWED_ORIGINS` env var must include the frontend
origin. The default is `http://localhost:3000`. If you serve the frontend on
a different port, update `.env` and restart the backend:

```sh
CORS_ALLOWED_ORIGINS=http://localhost:4000
docker compose restart backend
```

### Wipe everything

```sh
docker compose down -v
docker system prune
```
